# 工作流:四阶段执行细节

本文件是 SKILL.md 主流程的细化。每个阶段说明做什么、怎么判断、常见失败与纠正。所有阶段产出都应以文本/结构化清单形式呈现在回复中,证据链完整可回溯。

## 阶段 ①:输入判定与时间轴整理

### 判定输入形态

| 观察 | 判定 | 处理 |
|---|---|---|
| 图片含「朋友圈」标题栏/相机图标/封面区 | 首页时间线截图 | 注意区分顶部个人封面区与下方动态 |
| 图片只有连续动态、无首页元素 | 下拉滚动截图 | 同样有效 |
| 图片含聊天气泡、单条详情大图、评论全屏 | 非目标截图 | 拒绝并说明原因 |
| 不同动态的发布者昵称/头像不一致 | 混合信息流 | 拒绝,请用户只保留目标客户本人的动态 |
| 无法看清文字/图片过小 | 低质截图 | 请用户放大或分屏重截 |

### 多图时间轴处理

多张截图的价值在于**时间序列分析**,顺序错了结论就错了。处理步骤:

1. 优先读图内时间戳(动态发布时间),按时间排序。
2. 图内时间不可读时,从文件名提取(微信常见命名):
   - `mmexport<13位毫秒时间戳>.jpg`
   - `IMG_YYYYMMDD_HHMMSS.jpg`
   - `WeChat_YYYYMMDD_HHMMSS.jpg`
3. 可选:`python scripts/timeline.py <文件或目录> --out timeline.json` 输出排序清单。
4. 排序结果与截图内容有矛盾时(如文件名 2024 但内容是 2025 春节祝福),以**图内内容为准**并标注差异。

时间轴输出模板(供 LLM 自己维护,无需脚本):

```
时间轴(共 N 段,按时间升序)
- [约 YYYY-MM 或 "更早"] 截图 A:动态要点 1~2 条(简短)
- [YYYY-MM] 截图 B:动态要点 1~2 条
...
```

时间跨度 < 2 周的截图:时间序列层价值有限,如实说明"近期动态为主,变化分析置信度低",跳过趋势推断。

## 阶段 ②:商业画像解读

读取 [client-profile-model.md](references/client-profile-model.md),按维度清单逐项提取。执行规则:

- **每一条画像结论 = 证据 + 置信度**。证据引用动态原文或视觉特征;无法从截图确认的写"未观察到"。
- 维度宁缺毋滥:信息不足的维度不猜。猜错比不猜更伤信任。
- 输出格式建议(可并入最终报告第一部分):

```
■ 客户商业画像(基于可见朋友圈,置信度:高/中/低)
  基础身份线索:……(证据:……)
  生活方式与消费力:……(证据:……)
  兴趣与关注点:……(证据:……)
  表达与沟通风格:……(证据:……)
  沟通路径建议:……(从风格推导,1-2 条可执行建议)
  未观察到:……
```

## 阶段 ③:信号提取与行动建议

读取 [signal-guide.md](references/signal-guide.md)。这是**核心交付**,必须完整:

- 把全部动态过一遍信号清单,能匹配的逐条列出:信号类型 + 证据 + 触发动作。
- 多条信号并存时按优先级排序(⚫ 流失 → 🟠 负面情绪 → 🟡 生活事件 → 🔴 购买),先处理高优先级。
- **没有信号就不要硬造**。输出"当前未观察到明确购买/生活事件信号",并给出保持联系的日常动作(P2 级),比编一条假信号专业得多。
- 每条行动建议给出:动作、话术示例(改写行业模板)、建议时机。

## 阶段 ④:物料产出

### 话术包

- 先给一条主话术(可直接复制发送),再给两条备选(不同语气:稳妥型/轻松型)。
- 话术要"去行业痕迹":模板中的行业词换成客户实际情况,读起来像你本人写的,不像群发。
- 附发送建议:时段(工作日 20:00-21:00、周末上午)、入口(直接私聊 vs 评论互动先行)。

### 海报/配图

- 只有在用户明确要求时才进入海报流程(生图消耗资源/额度)。
- 严格按 [poster-playbook.md](references/poster-playbook.md):先定核心信息与画布,确认后再执行;中文文案 ≥8 字走背景图+本地叠字。
- 交付时说明:画布、核心信息、使用了什么生图通道、需要用户确认后发布。

### HTML 客户档案卡

用户要求"存档/留着下次跟进"时:

1. 把本次分析整理为结构化 JSON(字段见 scripts/make_profile_card.py 的 README 注释与 --help)。
2. `python scripts/make_profile_card.py profile.json -o 客户_<姓名>_档案.html`
3. 交付 HTML 路径,说明可离线打开、下次跟进可复用同一档案追加新证据。

## 失败模式与纠正(总表)

| 失败模式 | 后果 | 纠正 |
|---|---|---|
| 截图顺序搞反 | 时间序列结论反向 | 双来源校验(图内时间+文件名),矛盾以图内为准 |
| 脑补缺失信息 | 画像失真,客户跟进方向错误 | 只写"观察到"与"未观察到",缺项明确标出 |
| 硬造购买信号 | 过早推销,破坏关系 | 无信号就如实说,给 P2 保持联系动作 |
| 话术模板原样照搬 | 客户一眼看出群发 | 改写至口语化、贴合客户动态细节 |
| 让生图模型渲染长中文 | 海报出现错字 | 中文 ≥8 字一律本地叠字(见 poster-playbook.md) |
| 对无关陌生人做深度分析 | 合规风险 | 场景限定拦截,见 ethics-guardrails.md |
